# Streamed agent supervision and independent review deadlines

**Status:** Draft
**Review:** Unreviewed
**Target:** v0.2 (before long-running parallel self-hosting)
**Filed:** 2026-08-15
**Origin:** owner prompts and three failed self-hosted Tactus runs, 2026-08-13–15.

---

## Summary

Tactus should supervise agent CLIs as typed streams rather than waiting for one
opaque terminal response. The runner records bounded private output, adapters
decode vendor-specific frames into a small provider-neutral activity model, and
status exposes sanitized milestones without pretending to know a percentage.

Each model invocation receives its own deadline. In particular, each mandatory
review pass gets the complete configured review allowance rather than sharing a
task-wide fuse with implementation, gates, or another reviewer. Timeout,
transport failure, or a missing terminal result still fails closed.

## Why now

Three self-hosted runs demonstrated the same structural failure:

- implementation and repository gates completed successfully;
- a frontier review was running and sometimes visibly making progress;
- the current shared wall-clock expired before the reviewer settled;
- Tactus discarded the candidate and repeated expensive implementation;
- partial reviewer output could not be used to distinguish progress from a
  stalled process, and child-process cancellation was imperfect.

Parallelism would multiply this waste and make a silent stuck worker harder to
diagnose. Supervision is therefore a reliability prerequisite, not a UI extra.

## Proposed protocol

### Provider-neutral stream

`Runner::run` accepts an activity sink and emits ordered `ProcessFrame` values:

- stdout bytes;
- stderr bytes;
- heartbeat with elapsed and idle duration;
- process start, exit, timeout, and cancellation facts.

Every `AgentAdapter` supplies an `AgentStreamDecoder` that incrementally maps
those frames into typed `AgentActivity` values such as:

- session identity observed;
- model invocation active;
- tool invocation active;
- provider retry or backoff;
- idle heartbeat;
- terminal structured result.

The runner owns process lifetime and bytes. The adapter owns vendor syntax. The
engine consumes only typed activity and the final adapter result.

### Evidence and privacy

Raw stdout/stderr is incrementally spooled to the private run store under a
bounded retention policy. Generated prose, tool arguments, file contents, and
chain-of-thought-like material never enter the canonical event log.

The public event stream may contain rate-limited, sanitized milestones such as
`review active`, `tool active`, `provider retrying`, or `idle for 300s`. It must
not expose raw model output and must never invent a completion percentage.

### Time and liveness

Initial defaults proposed for council:

- implementation invocation: 30 minutes;
- each review pass: 90 minutes;
- heartbeat: 60 seconds;
- informational idle warning: 300 seconds.

The review deadline is per pass. A re-ask shares that pass's deadline, but a
second mandatory reviewer receives a fresh full deadline. Heartbeats and idle
warnings do not extend deadlines and do not convert silence into failure.

Cancellation terminates the complete supervised process tree. A timeout or a
transport ending without one valid terminal result settles `Unavailable`,
preserves the partial private transcript, and never infers a verdict from a
prefix.

### Resume

Capture a provider session identity as soon as the stream makes it available.
Resume is permitted only when its semantic workspace still exists:

- implementation may resume only with the exact retained generation and tree;
- review may resume only for the exact candidate, pass slot, prompt contract,
  and evidence digest;
- otherwise the interrupted invocation remains recorded and a fresh invocation
  follows the normal retry policy.

An adapter that cannot safely resume simply reports that capability as absent.

## Relationship to parallel execution

This proposal changes supervision, not scheduler ownership. The adopted
[merge-queue topology](../decisions/2026-08-12-merge-queue-execution-topology.md)
still lands sequentially at `max_parallel = 1` before Tokio dispatch.

The parallel implementation should begin by extracting only the boundaries it
needs from `engine.rs`—ordered task registry, readiness/admission, task
pipeline, integration queue, and coordinator—while preserving behavior. The
split is parallelism phase zero, not a general cleanup project. Existing broad
engine tests may remain in place until those module boundaries stabilize.

## Acceptance criteria

1. Fragmented and interleaved stream frames decode deterministically.
2. Initialization, activity, retry, silence, and one terminal result are
   distinguishable without inspecting prose.
3. One slow review cannot consume another review pass's deadline.
4. Timeout and cancellation terminate the complete owned process tree on every
   supported platform.
5. Private transcripts are bounded and recoverable; public events contain only
   sanitized milestones.
6. A killed invocation never becomes a pass, and an ambiguous post-dispatch
   retry cannot silently buy a fresh judgment.
7. Existing non-streaming adapters remain supported through a compatibility
   decoder that emits only lifecycle and terminal facts.
8. Status can show elapsed/idle activity but never a fabricated percentage.

## Non-goals

- changing review quality policy or model selection;
- exposing raw model streams in a public viewer;
- treating activity as proof of useful progress;
- implementing parallel scheduling in the same change;
- vendor-specific logic in the engine.

## Open questions for council

1. Which activity values are safe enough for the public event log by default?
2. Should transcript byte limits be global, per invocation, or both?
3. Which providers support idempotent recovery of a dispatched invocation?
4. Should operator-configured deadlines be role defaults, route overrides, or
   both?

Watch it fail safely

An agent wrote code that compiled clean and passed all 722 tests. It was still wrong.

This is captured output from two real runs, and it is worth being precise about which is which. The verdict, the dry run and the branch below come from a run against FluentRoslyn, a published .NET library, fixing two open findings from its own code-review log. The interactive replay and the ledger come from the acceptance run that proved the engine, against a scratch repository. Nothing here is reconstructed, but nothing here is one continuous run either.

The claim worth testing is narrow and falsifiable: gates are not enough, and a reviewer from a different model family catches things no gate can. What follows is one case where that happened, with the receipt.

Before spending anything

A dry run costs nothing and answers the two questions worth asking first — what will it do, and what could it cost.

Note what it declines to claim. No pool reports "full" — it reports unknown, because nothing has measured it yet. A capacity estimate that flatters is worse than none.

The catch

Back to FluentRoslyn, and to the moment that makes the case. Its first attempt produced a fix that built cleanly and passed all 722 tests. The reviewer — a different model from the one that wrote it — rejected it anyway:

Negative zero is emitted as System.BitConverter.Int64BitsToDouble(...), which is not a compile-time constant. FieldBuilder.WithInitializer is reachable with Const(), so a const float/double field initialized from -0.0 now fails in the consumer with CS0133. That case compiled before this change.

claude-opus-5, reviewing work by claude-haiku-4-5

No gate could have caught that. The code compiles — in this repository. It breaks in a consumer's build, in a case the test suite never exercises, and it silently removes a capability that previously worked. The reviewer also knew that Int32BitsToSingle does not exist in the library's netstandard2.0 target, pointed at the two files where the codebase already solves this correctly, and cited the duplication cluster closed three commits earlier. It had read the git history.

The retry resumed the same session with that verdict fed back, and the second attempt shipped the correct fix: a prefix-minus over an explicitly floating-point token, which stays a compile-time constant.

Where the work landed

What this does not show

It cost $12.44 to fix one finding, and the run stopped at its ceiling before reaching the second. Review was roughly half of that, and on this evidence it is the half that earns its keep — but it is not cheap, and anyone deciding whether to adopt this should price it at $3–12 per real task rather than from a toy example.

Nor is any of this deterministic. The same task, on the same model, from the same commit, failed review in one run and stopped to ask a question in another. That is worth stating plainly, because it means a single run proves less than its clean numbers suggest — including the runs on this page.

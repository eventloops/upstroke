## Failure sequence

`stable_content` filters the one volatile line of the pools file by the literal
`"# Written by \`upstroke connect\`"`; the renderer writes that line from its own spelling. At
`323beb0b1b3ebc2ab645bf10f1cfde81d2b7250b` both were bare literals in two files. Change the header's first words
in the renderer and the filter matches nothing: every `connect` on an unchanged machine reports
`Written` and rewrites the file for its timestamp, and `unchanged` is never reported again.

**And nothing in the suite noticed.** Measured at `323beb0b1b3ebc2ab645bf10f1cfde81d2b7250b`:
renaming the header's first word (`# Written by` -> `# Generated by`) in the renderer and running
the whole suite gave **1925 passed, 0 failed**. The test that looks like the guard,
`re_connecting_an_unchanged_machine_reports_unchanged_rather_than_a_conflict`, runs its two
connects within one second, so both files carry the same timestamp and compare equal whether or
not `stable_content` filtered anything — it pins the `Unchanged` answer for an unchanged file, and
says nothing about the one line that is supposed to be allowed to move. The same holds if the
filter is deleted outright.

PR #155 names the renderer's spelling `render::WRITTEN_BY`, documents the coupling on it, and pins
the literal in `the_header_prefix_is_the_literal_the_parent_filters_by`, whose comment says why;
the parent's literal stands, so the two are still spelled twice.

## Why this is recorded rather than fixed

One line in the parent (`.starts_with(render::WRITTEN_BY)`) and one test with a controlled
timestamp, but the parent is row 57's and this sweep's bound is its own file. The render-side test
is the guard meanwhile.

## What the change that takes this up should do

Read `render::WRITTEN_BY` in `stable_content` and delete the parent's literal. Give the parent's
`Unchanged` test a second connect whose header timestamp differs from the first — `pools_file_at`
exists for that, or the test can rewrite the written-by line between the two connects — so that
the test fails when the filter stops filtering.
